The short version

Almost every “best mini PC for Home Assistant” list gets the framing backwards. They rank boxes by raw power, when the real story is that Home Assistant barely needs any. It runs happily on a 2GB Raspberry Pi, and the official Home Assistant Green appliance ships with a quad-core Arm chip and just 4GB of RAM. So the question is not “how much CPU do I need for Home Assistant?” — it is “what is the most reliable, low-power box that will still have headroom in three years?”

The answer, for most people, is a new Intel N100 mini PC with 16GB of RAM and an SSD. It’s cheap, sips 7–14 watts, is silent, and — importantly for cameras — its integrated GPU includes Intel Quick Sync. If you’re comfortable buying used, a refurbished enterprise micro (a Dell OptiPlex Micro or Lenovo ThinkCentre Tiny) gives you a 6-core i5 and a Windows license for a bit more idle power and often less money. You only step up to something bigger for two specific workloads — a busy Frigate camera setup or local voice — which we’ll size precisely below. If you plan to run Home Assistant as one VM among several services, our Home Assistant on Proxmox guide covers that install; if you want a bigger virtualization host in general, see the best mini PCs for a homelab. This page is specifically about the smart-home box.

What Home Assistant actually needs

Home Assistant doesn’t publish a single tidy “recommended specs” table for an x86 mini PC, so here is what the official docs do say, and what it means:

  • The only hard minimum is the Pi figure: the Raspberry Pi install page calls for “minimum 2 GB RAM” and a card “at least 32 GB.” That’s the floor for Home Assistant by itself.
  • The official appliance is 4GB. Home Assistant Green — the box the project sells for people who don’t want to think about hardware — has 4GB of RAM, 32GB of eMMC, and a modest quad-core Arm CPU. If that runs Home Assistant well, a 6-watt N100 with 16GB obliterates the requirement.
  • On x86, use an SSD, not an SD card. The generic x86-64 install docs assume an internal S-ATA/M.2 SSD or eMMC boot medium; the machine just needs to be 64-bit and boot via UEFI, which covers essentially every mini PC made in the last decade.

The practical takeaway: buy for headroom and reliability, not benchmarks. 16GB of RAM and a 256–512GB SSD is the community’s comfortable sweet spot — not because Home Assistant needs it, but because add-ons, a few months of history, and future tinkering do, and because RAM and an SSD are cheap insurance against ever thinking about it again.

Why a mini PC beats a Raspberry Pi

The single most common Home Assistant hardware story on the forums is an SD card dying. Home Assistant writes to its database constantly (every sensor update, every state change), and that steady write load chews through Raspberry Pi SD cards — users routinely report two or three dead cards in a year, even on premium and “industrial” cards. The fix is always the same: move to a real SSD.

A mini PC solves that by default — it boots from a SATA or NVMe SSD that laughs off Home Assistant’s write pattern. On top of that you get far more CPU and RAM headroom than a Pi, USB 3.0 ports, and a real SSD in place of a wear-prone card — and once you add a Pi’s case, power supply, and SSD, a used mini PC often isn’t much more expensive anyway. A Pi is a fine way to learn Home Assistant. A mini PC is where you put it when you want to stop maintaining the hardware.

The N100 (and N150): the low-power sweet spot

The chip at the center of nearly every good Home Assistant mini PC is the Intel Processor N100. Per Intel’s ARK spec page, it’s a 4-core / 4-thread part (all efficient Gracemont cores) with 6MB of cache, a 6-watt base power, up to 3.40GHz turbo, and an Intel UHD integrated GPU with 24 execution units. Two specs matter most for a smart-home box: it officially tops out at 16GB of RAM (single channel), and its iGPU includes Intel Quick Sync Video — the hardware video engine that makes Frigate practical (more on that next).

You’ll also see the newer Intel N150 in 2026 boxes. Don’t overthink it: per Intel ARK, the N150 (code-named Twin Lake) is a minor refresh of the same Alder Lake-N-class silicon. The only spec changes are a slightly higher CPU turbo (3.60GHz vs 3.40GHz) and a slightly higher iGPU clock (1.0GHz vs 750MHz). Same 4 cores, same 6-watt power, same 16GB memory ceiling, same 24-EU iGPU, same Quick Sync. For Home Assistant, an N100 and an N150 are functionally identical — buy whichever is cheaper.

One honest caveat on RAM: Intel’s official ceiling for both chips is 16GB, but many vendors advertise and ship 32GB single modules that work in practice. Treat anything above 16GB as board-dependent rather than an Intel guarantee — and for Home Assistant, 16GB is already more than you need.

When to actually size up: Frigate and voice

If you only run Home Assistant plus normal integrations and add-ons, an N100 is overkill and you can stop reading and buy one. Two workloads change the math:

Frigate NVR (cameras). Frigate is CPU-hungry in one specific way: decoding camera video streams. Frigate’s docs say it is “highly recommended to use an integrated or discrete GPU for hardware acceleration” because decoding camera streams is the CPU-heavy part. Here’s the good news that the buying guides bury: the N100’s Quick Sync already does this, and the same iGPU runs object detection through Frigate’s OpenVINO detector — so a single N100 box handles both jobs. That’s why Frigate’s own recommended hardware list includes an N100 mini PC (the Beelink EQ13), which “can run object detection on several 1080p cameras with low-medium activity.” Note what you don’t need: Frigate now says the Google Coral is “no longer recommended for new installations” (outside niche ultra-low-power builds) and points out that “the Coral does not help with decoding video streams” anyway. Skip it. You move up to a 6–8 core i5 or Ryzen (and more RAM) only when you run many cameras, higher resolutions, or high-activity scenes. Storage scales with exactly the same three inputs — the Frigate NVR storage calculator turns camera count, resolution, and retention days into a drive size and the /dev/shm value Frigate needs. If cameras are the main job rather than a side workload for a smart-home box, we size a dedicated NVR by camera count — and cover the surveillance-drive pricing traps — in best hardware for Frigate NVR.

Local voice (Whisper). Running your own speech-to-text with Whisper is the other real load. Home Assistant is blunt about it: Whisper “is only a great option” if “you have powerful hardware at home,” noting that a task taking ~8 seconds on a Raspberry Pi 4 is “done in under a second” on an Intel NUC. And the largest Whisper models “require a GPU” and are “unusable on a Raspberry Pi or even an N100-class PC.” The lighter Piper text-to-speech is not the bottleneck. Translation: an N100 handles basic local voice fine, but a serious multi-language voice assistant is a reason to go bigger.

The recurring community wisdom, and it’s good advice: don’t pre-buy headroom. Start with an N100 or a refurb i5, measure your real CPU and RAM once your cameras and add-ons are running, and upgrade only if the numbers say so.

The barebone trap (the one 2026 twist)

Here’s the money-saving detail every competing guide misses. Because of the 2026 memory shortage, RAM prices have spiked — so a “cheap” barebone mini PC is now the most expensive way to end up running. Buy the barebone, add your own RAM and SSD, and you often pay more than a complete box that already includes them. A live example from this same July 20 pull: GMKtec’s G3 Pro is $189.99 barebone (no RAM/SSD/OS) versus $329.99 complete with 16GB, a 512GB SSD, and Windows — and in 2026 that RAM, SSD, and license cost more than the $140 gap if you buy them separately. The rule: for a Home Assistant box, buy it complete, or buy a used machine that already comes with RAM. The sticker price on a barebone is a down payment, not the total.

The Zigbee / Z-Wave USB gotcha nobody warns you about

This one bites almost everyone, and it’s the difference between a rock-solid smart home and mysterious dropouts. When you plug a Zigbee or Z-Wave/Thread USB stick directly into a mini PC — especially next to a USB 3.0 or USB-C port — the high-speed USB signaling raises the noise floor in the 2.4GHz band and cripples your Zigbee/Thread network. This isn’t folklore; it’s official Home Assistant ZHA guidance: “Make sure to only connect the Zigbee USB adapter to a USB 2.0 port (and not to a USB 3.x port)”, and place it away from interference “preferably by using an adequately long shielded USB extension cable.” Home Assistant’s own Connect ZBT-2 adapter even ships with a 1.5-meter cable and a free-standing base specifically because “USB ports and nearby electronics can create interference.” So: USB 2.0 port + a meter of shielded extension cable, stick standing away from the box. It costs a few dollars and saves hours of debugging.

HAOS bare metal or a Proxmox VM?

Two good options, one clear loser:

  • Home Assistant OS, bare metal — the officially recommended install for most users. If the mini PC will only run Home Assistant, do this: it’s appliance-like, updates and backups live in the UI, and there’s no command line. This is the right default for an N100 box dedicated to the smart home.
  • HAOS in a Proxmox VM — the community favorite when the box will also run other things (Pi-hole, Plex, a Frigate container, a NAS role). You get VM snapshots, the ability to hard-restart Home Assistant remotely if it hangs, and room to run everything on one machine, with negligible performance loss. Our step-by-step Home Assistant on Proxmox guide walks through it, including USB passthrough for your Zigbee stick.
  • Supervised on Debian — the least-recommended path; you’re on your own for support if you install other software alongside it.

Simple rule: only Home Assistant → HAOS on the metal. Home Assistant plus other services → HAOS in a Proxmox VM.

What competing guides skip (our angle)

Most “best mini PC for Home Assistant” pages are a list of Beelink boxes with affiliate links. What they consistently miss, all covered above:

  • That Home Assistant is tiny — they rank by CPU power when the real buying axis is SSD reliability + headroom, and they never mention the official 4GB Green box as the baseline.
  • That Frigate needs no Coral on an N100 — the N100’s Quick Sync does the decode and OpenVINO does the detection on the same chip; Frigate itself now deprecates the Coral for new installs.
  • The Zigbee USB-3 interference fix — official ZHA guidance that turns a flaky network solid, absent from nearly every hardware list.
  • The 2026 barebone trap — with RAM prices spiking, a complete box beats a barebone, the opposite of the usual advice.

Frequently asked questions

What is the best mini PC for Home Assistant in 2026?
For most people it is a new Intel N100 (or N150) mini PC with 16GB of RAM and a 256-512GB SSD - the Beelink S12 Pro is the usual community pick at around $339 in our July 20, 2026 snapshot. It sips power (around 10-14W idle), and its Intel Quick Sync handles Frigate video decoding. If you are comfortable with used gear, a refurbished enterprise micro - a Dell OptiPlex Micro or Lenovo ThinkCentre Tiny with a 6-core i5 - is the better value at roughly $150-250 and includes a Windows Pro license, at the cost of a few more watts at idle.
Is an Intel N100 enough for Home Assistant?
Yes, comfortably. Home Assistant itself is tiny - it runs on a 2GB Raspberry Pi, and the official Home Assistant Green box ships with just 4GB of RAM. A 4-core, 6-watt N100 with 16GB of RAM has plenty of headroom for Home Assistant plus a normal add-on stack, and even for running it in a Proxmox VM alongside a few other services. The community’s repeated advice is not to over-buy. You only need to size up for heavy Frigate camera setups or local voice (Whisper), which are the two workloads that actually stress a small box.
How much RAM and storage does Home Assistant need?
Home Assistant’s only official quantified minimum is the Raspberry Pi figure: 2GB of RAM and a 32GB card. The official Home Assistant Green box uses 4GB of RAM and 32GB of eMMC. That is ‘Home Assistant alone.’ For a mini PC where you will run add-ons and want years of headroom, the community sweet spot is 16GB of RAM and a 256-512GB SSD. The most important storage rule is to use a real SSD (SATA or NVMe), never an SD card - on x86 the official docs assume an internal SSD or eMMC boot medium.
Can a mini PC run Home Assistant and Frigate NVR at the same time?
Yes. An Intel N100 can run Home Assistant and Frigate together for several 1080p cameras at low-to-medium activity, per Frigate’s own hardware notes. The N100’s integrated GPU provides Intel Quick Sync, which Frigate ‘highly recommends’ for the CPU-heavy video-decoding job, and the same iGPU runs object detection via OpenVINO - so you do not need a Google Coral. Frigate now lists the Coral as ’no longer recommended for new installations.’ You size up to a 6-8 core i5/Ryzen only when you run many cameras, high resolutions, or high-activity scenes.
Is a mini PC better than a Raspberry Pi for Home Assistant?
For a 24/7 setup, yes. Home Assistant writes to its database constantly, and that write load wears out Raspberry Pi SD cards - the community forums are full of people losing two or three cards in a year, even premium ones. A mini PC boots from a real SSD that shrugs off those writes, gives you far more CPU/RAM headroom, and in 2026, once you add a Pi’s case, power supply, and SSD, a used enterprise micro often isn’t much more expensive. A Pi is great for learning; a mini PC is the reliable long-term home.
Should I install Home Assistant OS bare metal or in a Proxmox VM?
If the mini PC will only run Home Assistant, install Home Assistant OS (HAOS) directly on the metal - it is the appliance-like, officially recommended path, with UI updates and built-in backups and no command line. If the box will also run other services (Pi-hole, Plex, a Frigate container, etc.), install HAOS as a VM under Proxmox instead: you get snapshots, remote hard-restart if HA hangs, and room to run everything on one machine, with negligible performance loss. Supervised-on-Debian is the least-recommended option.
